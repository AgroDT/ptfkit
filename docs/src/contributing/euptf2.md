# EU-PTF v2 native THS model

The [model collection guide](euptf2-collection.md) extends this validated
reference slice. This page retains its original artifact contract and audit.

ptfkit supports locally imported **THS_PTF01** from EU-PTF v2 in Python,
Rust, C11 and C++23. This first slice predicts saturated volumetric water
content and its conditional quantiles at 0.05, 0.5 and 0.95. Runtime inference
requires neither R nor a machine-learning framework. Trained parameters and
upstream R code are not included in ptfkit packages.

## Scientific source and provenance

The scientific source is [Szabó, Weynants and Weber (2021),
doi:10.5194/gmd-14-151-2021](https://doi.org/10.5194/gmd-14-151-2021).
The [archived scientific release v.2.0.0](https://zenodo.org/records/3759443)
corresponds to `brigittaszabo/euptfv2` commit
`35e2df971259f8f1d9904c5d0359eb09406175b1`. Zenodo publishes the archive MD5
`b539b7f92ff217c39d8c0f1c2375c5d4`; this is recorded as a published checksum,
not a locally verified download of that archive.

The executable reference is the unmodified [euptf2 1.0.0 R package](https://github.com/tkdweber/euptf2/tree/f22c38f7e73819ad23d7f6ff00b970288a7d57d0),
tag `v1.0.0`, commit `f22c38f7e73819ad23d7f6ff00b970288a7d57d0`.
All five `data/THS_PTF0N.rdata` Git blob IDs match the corresponding
`suggested_PTFs/THS_EUHYDI/` files in the archived scientific release.
`specs/models/euptf2/manifest.json` pins the downloaded package archive SHA-256,
the source, documentation and five THS RData SHA-256 checksums, predictor
contract, reference environment and converted artifact identity. Archives
generated by GitHub can change packaging bytes; the per-file hashes are the
offline import contract. Git checkouts should preserve original file bytes
(disable automatic line-ending conversion).

Upstream publishes GPL-3 licensing. The local source and converted trained
data remain external to ptfkit release packages. The importer and native
inference code are ptfkit implementations; they do not contain upstream R
source or trained arrays. No model is retrained.

## What the original objects preserve

The frozen `specs/models/euptf2/reference.json` records the actual R inspection
of all five THS objects, including classes, member names, forest metadata,
predictor ordering, response-matrix dimensions and leaf completeness.
Each object has class `ranger` and a `ranger.forest` regression forest with
200 trees and ordered numeric predictors.

| Object | Nodes | Leaves | Every leaf has a finite stored response |
| --- | ---: | ---: | --- |
| THS_PTF01 | 101822 | 51011 | Yes |
| THS_PTF02 | 221046 | 110623 | Yes |
| THS_PTF03 | 239876 | 120038 | Yes |
| THS_PTF04 | 50784 | 25492 | Yes |
| THS_PTF05 | 89590 | 44895 | Yes |

THS_PTF01 was trained on 3354 samples. Its `random.node.values` matrix is
643 by 200. Unused/internal entries can be NA; **every terminal entry needed
for new-data prediction is finite**. Its topology, split values, terminal
means and terminal response samples suffice for exact reproduction of
upstream new-data means and quantiles.

Ranger's implemented quantile algorithm selects the stored
`random.node.values[terminal_node, tree]` response for each tree, then computes
`stats::quantile(..., type=7)` on those 200 responses. These are sampled
training responses retained by ranger, not terminal means. The point estimate
is the arithmetic mean of the 200 terminal means from `forest$split.values`.
The converter preserves both values separately. It does not sample again.
The stored ranger distribution is sufficient for this upstream algorithm;
this does not assert recovery of the full training data or every response
in every leaf for a different QRF estimator.

The reference runtime is R 4.4.3 and ranger 0.18.0, both recorded explicitly.
The original training version is not encoded as a package-version field in
the inspected objects; the package declares ranger >= 0.10.1. The reference
runtime handles ranger's legacy response-inclusive split IDs. The converter
performs the same removal of the dependent-variable column without changing
thresholds or response samples. OOB state and in-bag counts are present but
are unnecessary for new-data inference. This slice does not expose OOB
predictions or standard errors.

## Predictor and result contract

Inputs are ordered exactly as the original forest:

| Original predictor | Meaning | Unit |
| --- | --- | --- |
| USSAND | USDA sand mass content | g / 100 g |
| USSILT | USDA silt mass content | g / 100 g |
| USCLAY | USDA clay mass content | g / 100 g |
| DEPTH_M | Mean soil horizon depth | cm |

`DEPTH_M` is **not metres**. The original sample-data documentation explicitly
states centimetres. Predictors have identity transforms. Splits route left
for `value <= threshold`. THS means and quantiles are in cm3/cm3, with identity
output transformation; there is no percentage conversion or logarithm.
The API does not renormalize texture, clip inputs or outputs, or downgrade to
another PTF. Outside-range numerical cases test computational parity, not
scientific applicability.

These APIs predict one complete row at a time. NaN denotes missing and returns
an input error, matching ranger's direct prediction contract. The R package's
table wrapper instead removes incomplete required rows and preserves their
original `OBS_ID` values; its recorded missing-data reference retains rows 1
and 3. A caller processing a table must apply that same complete-case filter
and retain row IDs before invoking the scalar API. No imputation is performed.
Infinities are not missing under R's `is.na` semantics and follow ordinary
ordered comparisons; they are not asserted to be valid soil measurements.

## Local import

Obtain the tagged source into an ignored local directory. R is needed only
for this offline conversion, which uses base R and never loads ranger or fits
a model. The Python wrapper authenticates all pinned files before R
deserialization, checks the resulting container's exact SHA-256 and byte
count, and creates a new output file exclusively.

```sh
git -c core.autocrlf=false clone --branch v1.0.0 https://github.com/tkdweber/euptf2 .euptf2-local/upstream
git -C .euptf2-local/upstream checkout f22c38f7e73819ad23d7f6ff00b970288a7d57d0
python codegen/scripts/import_euptf2.py --upstream .euptf2-local/upstream --output .euptf2-local/ths.ptfq
```

Use `--rscript /path/to/Rscript` if Rscript is not on PATH. The imported
container is 2851832 bytes, SHA-256
`44b0952dadae13f2081387a4b24efc54ba817b8275f3aff9a77e7bfcb322dc97`.
Repeated imports must be byte-identical. Do not copy it or the upstream
checkout into a target's release tree.

```python
from ptfkit.models import Euptf2Ths

model = Euptf2Ths.load('.euptf2-local/ths.ptfq')
mean, q05, q50, q95 = model.predict(40, 40, 20, 30)
```

Rust exposes `ptfkit::models::Euptf2Ths::load(path)` and
`model.predict([40.0, 40.0, 20.0, 30.0]) -> Result<[f64; 4], ModelError>`.
C11 exposes `ptfkit_euptf2_ths_load`, `ptfkit_euptf2_ths_from_bytes`,
`ptfkit_euptf2_ths_predict` and `ptfkit_euptf2_ths_free` through
`<ptfkit/ptfkit.h>`. C++23 exposes `ptfkit::Euptf2Ths` through `import ptfkit`,
with move-only ownership, `load`, `from_bytes` and `predict(std::array<double,4>)`.
All return mean, q05, q50 and q95 in that order. Changed artifacts are rejected
using the reviewed digest compiled into each target. Model data are owned,
so subsequent file changes cannot affect a loaded model. C initializes output
storage to NaNs on prediction failure. Existing model errors are reused.

## PTFKQF01 binary format

All integers are unsigned little-endian u32; numbers are IEEE-754 binary64
little-endian. The container starts with eight ASCII bytes `PTFKQF01`, then
contract ID `1` (THS_PTF01 predictor order and output scales above), then tree
count. Each tree starts with its node count, followed by 28-byte node records:
left child ID, right child ID, zero-based feature ID, split value/terminal
mean, and stored response sample. Root ID is zero. Leaves have both children
zero and feature ID `0xffffffff`. Internal samples are canonically zero.
Children must follow their parent and every non-root node must have exactly
one parent. Every numeric payload must be finite, including every leaf sample.

The complete container, including topology, is authenticated before decoding.
Decoders bound file size to 64 MiB and tree count to 1000, check sizes before
allocation, and reject truncation, trailing bytes, invalid feature IDs, cycles,
shared children, unreachable nodes and non-finite payloads. This version is
deliberately limited to numeric ordered predictors and the selected model.
It adds no categorical forest framework or alternate quantile algorithm.
The existing dense Rosetta format and kernels retain their numerical behavior.
All generated bindings come from `codegen/src/neural/qrf*` and the ordinary
generator; do not edit generated targets directly.

## Independent references and verification

The frozen 60-case reference was produced by the actual installed upstream
`euptf2::euptfFun` for both `query="predictions"` and `query="quantiles"`.
It includes ten upstream sample soils, twelve texture/depth extremes,
36 root-threshold probes and two out-of-range rows. The reference script reads
no converted artifact and calls no ptfkit inference. It also inspects all five
original THS objects and checks the upstream table wrapper's missing-row policy.

To recreate references, install R 4.4.3, ranger 0.18.0 and the upstream package
dependencies in a local R library, then install the authenticated upstream
source and run:

```sh
R CMD INSTALL --library=.euptf2-local/R-library .euptf2-local/upstream
Rscript --vanilla codegen/scripts/reference_euptf2.R .euptf2-local/R-library .euptf2-local/reference-repeat
```

The output directory must be new. Compare its `reference.json` with the frozen
fixture rather than replacing expected values from native predictions. The
manifest records the reference R installer hash, ranger DLL hash and hash of
the installed `predict.ranger` deparse used in this audit; upstream source and
the deparse remain local.

After normal generation and builds, run:

```sh
mise run generate-check
mise run verify
cargo build --manifest-path targets/ptfkit-rs/Cargo.toml --example euptf2_runner
uv run --project targets/ptfkit-py --frozen python codegen/scripts/verify_euptf2.py --model .euptf2-local/ths.ptfq --build targets/ptfkit-native/build/tests --rust targets/ptfkit-rs/target/debug/examples/euptf2_runner
```

On Windows, append `.exe` to the Rust runner path. This explicit local
integration check fails if the external model or any runner is absent.
The equivalent task is `mise run euptf2:verify-public .euptf2-local/ths.ptfq`;
it builds all runners and runs the component tests and the two offline
importer integrity tests. `mise run euptf2:import <upstream>` provides the
default local import when Rscript is on PATH.
The absolute reproduction tolerance is 2e-14 cm3/cm3, allowing binary64
addition and interpolation rounding over 200 trees, with no fitted tolerance
adjustment. It is distinct from scientific prediction error. Ordinary Rust
and C tests use independent hand-specified small forests with different
terminal means and response samples; taking percentiles of tree means cannot
pass them. Authenticated malformed-container tests exercise validation after
integrity verification. No upstream artifacts are required for ordinary tests.

Only THS_PTF01 is exposed in this first slice. Other predictor sets, arbitrary
quantile probabilities, table orchestration and other hydraulic targets remain
outside its scope. Computational parity does not establish predictive accuracy
for a new soil population.

also rejected all four missing-predictor cases and a changed artifact. Repeated
R reference generation was byte-identical, as was repeated offline conversion.
